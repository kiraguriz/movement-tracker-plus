How the columns are computed (`EvalReport.swift`):

- Exact count: clips whose counted reps equal the labelled reps.
- Within ±1 rep: clips whose counted reps differ from the label by at most one.
- Mean abs. error: the mean of |counted − labelled| over the labelled clips, in reps.
- False reps on idle clips: reps counted in clips labelled 0 reps (standing, walking away, holding a plank). It must be 0.
- Partial reps exact: clips whose counted partial reps (dips shown but not counted) equal the labelled number, among clips that have a partial label.

### What counts as a real set

`motion-eval` reads the expected counts from the fixture header (`labels.reps`, `labels.partials`) first and from the file name second (`<exercise>_<reps>[_<partials>]`, for example `squat.bodyweight_10_1_front.jsonl`). New iPhone recordings leave truth labels empty; older builds wrote the engine's own count, which is not ground truth. `tools/accuracy.sh` takes a file only after `tools/import-fixture.sh` has set the counts a person gave and added the `verified` tag. Files tagged `synthetic` or `replay`, or without a front or back camera position, are never counted as real.

## Synthetic benchmark

`motion-eval --synthetic`. **Generated motion, not people.** A scripted stick figure (`SyntheticMotion` in MotionCore) performs each clip with seeded random noise on the joints (`Noise.visionLike`: white noise plus a slower wander, sized to look like Vision on a still person) and the engine counts it. The clips cover different tempos, pauses at the bottom, fatigue, partial reps, joint dropouts, both facings and idle clips (standing, walking out of frame and back, holding a plank). Everything is seeded, so every run prints this table. It tests the counting logic against known truth. It does not test how well Vision tracks a real body, and the noise model has not been compared with recorded Vision output. The engine's thresholds were tuned against this generator and its noise (`docs/rebuild-brief.md` §6.5), so this is not a held-out test.
